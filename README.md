# サブスク荘

自分が契約しているサブスクを、アパートの間取り図にして見える化する Web アプリ（PWA）です。
サブスク1つが1部屋。部屋の広さは払っている額で、**1畳＝年1万円**（設定で 5千円／2万円にも変えられます）。
「知らないうちに払っているお金をなくす」「お金の配置を整える」ことが目的で、家計簿ではありません。

- サーバーなし。データはブラウザ（localStorage）の中だけに保存し、外には送りません
- スマホのホーム画面に追加して使えます。オフラインでも開けます
- ビルド不要の素の HTML / CSS / JavaScript。実行時の依存ライブラリはありません

## 言葉

| アプリの言葉 | 意味 |
|---|---|
| 部屋・入居 | 確認済みの契約。合計・間取り・支払いに入るのはこれだけ |
| 入居希望者 | 明細やメモから見つけた「たぶんサブスク」の候補。審査（確認）して入居させるまで合計には入らない |
| 内見中 | 無料体験中 |
| 様子見／退去予定 | 状態タグの「見直す」「解約予定」 |
| 退去 | 解約済み。退去の記録に残り、浮いたお金を数え続ける |
| 押入れ | 1畳に満たない小さなサブスク |
| 手取りの家 | 手取りぜんぶを家にした間取り（家賃・通信費・サブスク棟・リビング＝自由に使えるお金） |

## できること

| 画面 | 内容 |
|---|---|
| はじめての説明 | 初回に4枚の説明と、手取りの入力（月でも年でも）。スキップ可、設定からもう一度見られる |
| ホーム：広さ | サブスクに貸している広さ（〇畳・「1LDKくらい」）、年額・月額、手取りに対する割合 |
| ホーム：お知らせ | 入居希望者が待っている／内見（無料体験）がもうすぐ終わる／今月の見回り／最近値上げした部屋／金額が分からない部屋 |
| ホーム：間取り | 部屋の広さ＝金額の間取り図。カテゴリで色分け、内見中・値上げ・様子見・退去予定の札。月額／年額の切り替え。部屋をタップすると詳細 |
| ホーム：手取りの家 | 手取りぜんぶを家にして、家賃・通信費・サブスク棟・リビング（自由に使えるお金）の広さを並べる |
| ホーム：模様替え | 部屋を選ぶと空き部屋になり、ひろくなる畳数と浮く額（月・年）が出る。そのまま「退去予定」にできる |
| ホーム：画像で保存 | 間取り図を画像にして共有・保存（金額を隠すこともできる） |
| ホーム：支払い | これからの支払いをリストかカレンダーで。内見おわり・年払いは目立たせる |
| 部屋の詳細 | 次の支払い、入居からの累計、金額の推移（値上げの記録）、見回りの記録、状態、解約ページ、「解約した（退去）」 |
| 見回り | 月に1回、部屋ごとに「今月使った？」を3択で。使っていない部屋は模様替えでそのまま試せる |
| 入居希望 | カード明細 CSV から定期課金を検出／雑入力（「ChatGPTとClaudeと…」）を分解／審査して入居させる。2回目以降は値上げを知らせる |
| 部屋 | 住んでいる部屋・様子見・退去予定の一覧と編集、退去の記録（浮いた額・再入居） |
| 設定 | 手取り（月／年で入れる）・家賃・通信費・ドル円レート・1畳あたりの額、テーマ、JSON バックアップ、支払日の .ics 書き出し |

**入居希望者（検出候補）と部屋（確認済みの契約）は分けています。** 合計・間取り・支払いに入るのは、入居させた部屋だけです。

手取りは月でも年（ボーナス込み）でも入れられます。年で入れた場合は 12 で割って月として扱います。

初回はサンプルデータ入りで起動します（画面上部に表示。ホームか設定の「サンプルを消す」で消えます）。
入居希望の画面の「サンプルの明細で試す」で、CSV 取り込みの流れも試せます。

## 手元で動かす

Node.js（18 以上）があれば動きます。追加のインストールは不要です。

```bash
node tools/serve.mjs
```

ブラウザで http://localhost:5173/ を開きます（ES モジュールを使うので、HTML を直接ダブルクリックでは動きません）。

## テスト

```bash
npm test
```

Node 標準のテストランナーで、CSV の読み取り・定期課金の検出・雑入力の分解・間取り（畳・手取りの家）とタイムラインの計算・保存データの移行・.ics の書き出しを確かめます。
CSV の検出は次のケースを含みます。

- Shift_JIS の明細（テストの中で Shift_JIS のバイト列を組み立てて読む）
- 列の順番が違う明細（会員情報の行や合計行が混ざっていても、中身から日付・金額・利用先の列を推定）
- ドル建てで毎月額がぶれる請求（10% の幅で同じ課金とみなし、平均額にする）
- 単発の買い物の混入（候補にしない。辞書にあるサービスの1回だけは「確度 低」）
- 値上げ、App Store 内の別々のサブスク、年払い、請求が止まったもの、期間が重なる CSV

## GitHub Pages に公開する

パスはすべて相対なので、`https://ユーザー名.github.io/リポジトリ名/` のようなサブパスでもそのまま動きます。

1. GitHub で新しいリポジトリを作る（例：`subseat`）。公開範囲は Public（無料プランの Pages は Public リポジトリのみ）
2. このフォルダでリポジトリを作って送る

   ```bash
   git init
   git add .
   git commit -m "サブスク荘"
   git branch -M main
   git remote add origin https://github.com/ユーザー名/subseat.git
   git push -u origin main
   ```

3. GitHub のリポジトリ画面で **Settings → Pages** を開く
4. **Build and deployment** の Source を **Deploy from a branch**、Branch を **main** と **/ (root)** にして Save
5. 1〜2分で `https://ユーザー名.github.io/subseat/` に公開される（Pages の画面に URL が出ます）
6. スマホでその URL を開き、共有メニューから **ホーム画面に追加**

> データは端末ごとのブラウザに保存されます。公開しても、他の人にあなたのデータが見えることはありません。
> 同じ URL を友人に渡すと、友人の端末には友人のデータだけが入ります。

### Cloudflare Pages の場合

Workers & Pages → Create → Pages → Connect to Git でリポジトリを選び、
Framework preset は **None**、Build command は空、Build output directory は **/** にします。

### 更新するとき

ファイルを直して push すれば反映されます。Service Worker は「キャッシュを返しつつ裏で新しい版を取る」ので、
**2回目に開いたときに新しい版**になります。

- ファイルを増やしたら `sw.js` の `ASSETS` に追加する
- 大きく変えたときは `sw.js` の `VERSION` を上げる（古いキャッシュが消えます）

## データについて

- 保存先はブラウザの localStorage（キー `subseat:v1`）。ブラウザのデータを消すと消えます
- 端末を変えるときは、設定の「バックアップを書き出す（JSON）」→ 新しい端末で「バックアップを読み込む」
- iPhone では、ホーム画面に追加したアプリと Safari のタブは保存場所が別です
- カード明細の CSV は端末の中で読むだけで、保存もしません（検出した候補と、その根拠の数件だけを残します）
- 前の版「サブスク席」のデータは、開いたときに自動で間取りの版に移します（契約・候補・設定はそのまま）

## カード明細 CSV のコツ

- カード会社の会員サイトから、**数か月分（3〜6か月）**の明細 CSV をダウンロードして、まとめて選んでください
- 文字コード（Shift_JIS / UTF-8）と列の並びは自動で判定します。取り込み後の「読み取った列を確認する」で、どの列を使ったか確かめられます
- 1か月分だけだと「毎月出ている」が判断できないので、ほとんど候補になりません

## まだ作っていないもの

- 為替レートの自動取得
- メールの領収書・スクショからの取り込み
- アカウントと端末間の同期、ストア公開

食費などの日々の支出、契約理由のメモ、給料や固定費の細かい登録は、意図して入れていません。
